# Simple 模式 API Key 并发上限

仅 `RUN_MODE=simple` 启用。创建或编辑 Key 时设置 `concurrency_limit`：

- `0`：不增加 Key 独立限制，默认值兼容已有 Key。
- `1..2147483647`：该 Key 同时在途的最大请求数（含排队），例如 `3`。
- 更新时不传字段：保留原配置；传 `0` 清除独立限制。

用户总并发和上游账号并发仍独立生效，创建多把 Key 不增加用户总并发。
普通模式不显示配置，也不执行 Key 限制；保留数据库值以支持切换回来。

## 页面和接口

API 密钥的创建/编辑弹窗仅在 simple 模式显示“并发上限”。列表显示当前并发/上限。
沿用 `POST /api/v1/keys` 和 `PUT /api/v1/keys/:id`，请求和返回增加字段：

```json
{"concurrency_limit": 3}
```

## 执行语义

- Redis Lua 原子判断和占位，多实例共享上限。
- Key 饱和立即拒绝，不进入用户等待队列；HTTP 返回 429，错误标识为 `api_key_concurrency_limit`。
- Redis 准入失败返回服务不可用，不能放开受限制的请求；超时后补偿删除本请求可能已写入的槽位。
- 名额覆盖用户排队、账号排队和请求生命周期，正常结束、异常、客户端取消均回收，释放幂等。
- 长请求每 30 秒续期；续期失败或槽位丢失时取消请求，TTL 负责崩溃兜底。
- Responses WebSocket 复用现有逐轮用户槽位生命周期，空闲轮间不占请求名额。
- Live 会话计入同一 Key 上限，创建请求向 Live 租约交接时不重复计数。
- 修改后鉴权缓存失效，新请求及已有 Responses WebSocket 的下一轮采用新上限。临时刷新失败沿用最近一次成功读取的限制，Key 已删除时拒绝新轮次。
- 调低上限不会主动中断已准入的请求。

数据库迁移增加默认 0 的非负 INTEGER 字段。此功能不改变 simple 的日额度等计费规则，
也不把多个 Key 自动归并成同一个组员；独立组员预算仍需用户归属。

## 回归覆盖

- 用户排队期间同一 Key 不能绕过上限；取消排队和请求结束均归还名额。
- Redis 准入结果不确定时只清理本请求的槽位，使用独立的清理超时。
- 真实 Responses WebSocket 连续两轮验证启用、调低、清除上限，以及刷新失败时沿用最近一次限制。
- 普通模式兼容、用户总上限、原子准入、幂等释放和续期失效取消仍由原有测试覆盖。
